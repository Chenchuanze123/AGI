## 问题 1：Ollama 拉取模型时报错 `file does not exist` / 网络超时

**现象**：

- `ollama pull qwen3:4b-instruct-2507` 报错 `Error: pull model manifest: file does not exist`
- 后续下载 BGE 模型时报错 `wsarecv: An established connection was aborted by the software in your host machine.`
  **原因**：
1. 模型名称错误：`qwen3:4b-instruct-2507` 是 Hugging Face/ModelScope 的命名，Ollama 官方库对应的 tag 是 `qwen3:4b`。

2. 网络问题：国内直连 Ollama 官方源不稳定，导致下载中断。

3. 残留文件：下载中断后，本地残留了不完整的 manifest 文件。

4. **解决方案**：

5. **修正模型名称**：使用 `ollama pull qwen3:4b` 和 `ollama pull bge-m3`。

6. **使用国内镜像**（如果官方源依然超时）：
   
   ```powershell
   ollama pull modelscope.cn/Qwen/Qwen3-4B-Instruct-GGUF
   ollama pull modelscope.cn/BAAI/bge-m3
   ```

7. **清理残留**：进入 `C:\Users\你的用户名\.ollama\models\manifests`，删除对应的 `qwen3` 文件夹。

8. **配置环境变量**：设置 `OLLAMA_MODELS` 到非 C 盘路径（如 `H:\ollama`），并**彻底退出并重启 Ollama** 使其生效。

## 问题 4：CodeSplitter 报错 `DownloadError: Failed to download ... io: 你的主机中的软件中止了一个已建立的连接`

**现象**：
`tree-sitter-language-pack` 尝试从 GitHub Releases 动态下载 `parsers-windows-x86_64.tar.zst`，因网络问题超时。

**原因**：
国内网络访问 GitHub 不稳定，导致动态下载解析器失败。

**解决方案（推荐方案）**：
使用轻量级的 `tree_sitter_cpp` 包，并手动将解析器对象传给 `CodeSplitter`，彻底绕开动态下载。

```powershell
pip install tree_sitter tree_sitter_cpp
```

```python
import tree_sitter
import tree_sitter_cpp
from llama_index.core.node_parser import CodeSplitter

CPP_LANGUAGE = tree_sitter.Language(tree_sitter_cpp.language())
cpp_parser = tree_sitter.Parser(CPP_LANGUAGE)

cpp_splitter = CodeSplitter(
    language="cpp",
    parser=cpp_parser,  # 关键：传入预构建的 parser
    chunk_lines=40,
    chunk_lines_overlap=15,
    max_chars=1500
)
```

## 问题 5：Word 文档切片出现严重乱码

**现象**：
切片内容显示为 `/+&W;'rβu&~k8ekmX+1wUm۲M9aRTDYwSW7_.Xz@6E6k7pZBsMs...` 等随机字符。

**原因**：
`.docx` 本质是 ZIP 压缩包（二进制格式），不是纯文本。`SimpleDirectoryReader` 在未显式指定 `file_extractor` 时，自动推断机制可能回退到通用文本读取器，强行用某种编码（UTF-8/GBK）解码 ZIP 的二进制内容，导致乱码。

**解决方案（方案A）**：
显式指定 `DocxReader`，强制使用 `python-docx` 解析。

```powershell
pip install llama-index-readers-file python-docx
```

```python
from llama_index.readers.file import DocxReader
from llama_index.core import SimpleDirectoryReader

docx_reader = DocxReader()

word_documents = SimpleDirectoryReader(
    input_dir="./test_data",
    required_exts=[".docx"],
    recursive=True,
    file_extractor={".docx": docx_reader}  # 显式指定解析器
).load_data()
```

## 经验总结

1. **Ollama 模型名要用官方 tag**：不要混用 Hugging Face/ModelScope 的命名，`qwen3:4b` 才是官方 tag。

2. **显式指定读取器优于自动推断**：尤其是处理 `.docx`、`.pdf`、`.xlsx` 等二进制格式时，显式传入 `file_extractor` 能避免回退到通用文本读取器导致的乱码。

3. **`tree-sitter-language-pack` 动态下载是坑**：国内网络环境下，推荐用独立包（如 `tree_sitter_cpp`）并手动传入 parser 对象。

4. **代码切片和文本切片策略不同**：代码用 `CodeSplitter`（按 AST 结构切），文本用 `SentenceSplitter`（按句子边界切）。

5. **环境变量修改后必须重启服务**：Ollama 只在启动时读取一次环境变量，修改后必须彻底退出并重启。
